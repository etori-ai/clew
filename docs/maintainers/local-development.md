# Local development

For contributors running the full Clew application. Connector authors can start with the [connector quickstart](../guides/creating-a-connector.md), whose signed fixture check needs no running services. Read the [architecture overview](../architecture/overview.md) to understand the components started here.

Host commands below start Docker infrastructure; application commands run inside `clew-app-1` at `/workspace`. These instructions use the shared local Keycloak container and are not a production deployment recipe.

## Run it

Everything runs in Docker. Commands go through `docker exec` into the app container (Claude Code and most editors sit outside the devcontainer).

```sh
sh scripts/compose.sh up -d --build --wait              # the app image (Node 26.13.0 LTS + Bun 1.4.4), Postgres 17, the six fixture connectors and the local fake of Microsoft Graph
docker exec -w /workspace clew-app-1 bun install --frozen-lockfile
docker exec -w /workspace clew-app-1 bun run db:init     # Drizzle migrations
docker exec -w /workspace clew-app-1 bun run dev:connectors  # fills missing fixture registrations and follower bindings (D61)
docker start keycloak                                    # the shared local Keycloak 26.2 at keycloak.orb.local:8090
docker inspect keycloak --format '{{json .Config.Env}}' | docker exec -i -w /workspace clew-app-1 bun run auth:setup
sh scripts/calendar.sh start                             # Nextcloud CalDAV provider + Mailpit, seeded with synthetic people and meetings (Hillevi's and Hassan's calendars)
docker exec -it -w /workspace clew-app-1 bun run dev                 # BFF on :3000 and Vite on :5173, published as http://localhost:3020
```

Open http://localhost:3020. Synthetic accounts: `hillevi` (rektor, manager persona), `hassan` (undersköterska, employee persona) and `mikael` (systemförvaltare, `admin.connectors`). The calendars are a mixed estate (D11, D69): Hillevi and Hassan have Nextcloud calendars, which `calendar.sh seed` fills, and Mikael's calendar is Microsoft 365 over the stack's local fake of Microsoft Graph (the `graph` service), which seeds itself as it starts; `sh scripts/graph.sh seed` restarts it for a fresh seed. `CALENDAR_ADAPTER=microsoft365` or `=caldav` on the BFF binds every account to one of them. Passwords are generated by `auth:setup` into the ignored `.auth-test.env`; the BFF reads `apps/server/.env.local`, also ignored.

The cards on Hem come from the six fixture connectors in the stack, generic systems as independent services behind the connector protocol (D61): `hr` (Personalsystemet), `finance` (Ekonomisystemet), `incidents` (Avvikelsesystemet), `communication` (Kommunikation), `timesheet` (Tidrapporteringen) and `payroll` (Lönesystemet), under `connectors/`. Clew bundles only its core; the fixtures are registered like a vendor's connectors and show as such under Administration › Anslutna system. The five writable sources keep date-relative records and operation logs in their own SQLite volumes; payroll reads HR's HTTP feed. Bootstrap requires `CLEW_POC=true` outside production and creates only missing registrations/bindings. Repeating it preserves URLs, secrets, audiences, disabled states and watch windows. Refresh a changed manifest explicitly in Administration › Anslutna system; use `scripts/job-bind.ts` to deliberately change a binding. The bootstrap's `--within` applies only to a missing payroll binding. A code change in a connector is `sh scripts/compose.sh restart <service>`. To see what Clew does when a source misbehaves, set `FIXTURE_FAULT` on one service (`unavailable`, `slow`, `unauthorized`, `conflict` or `crash-after-commit`) in an override or with `docker compose run`, and read the connector's README for the switches it supports.

## Reset fixture data deliberately

Stop Clew's BFF and its embedded worker before running `bun run fixtures:reset` (host or container with Docker access).
The command refuses while the local BFF is answering. Keep all other BFF/worker processes stopped until it finishes.
It then stops the six sources, retires their old work in one audited database transaction, removes only the five named
fixture volumes, and restarts the sources with fresh records. A failed volume removal stops the reset.

Old receipts and approved inputs remain historical. Undispatched decisions become failed; dispatched unresolved
decisions stay unknown. Both are marked `source-reset`, so neither replay nor compensation can reach fresh source data.
Waiting fixture watches are blocked, reminder timers cancelled and old card actions removed. Archived grouping keys
allow a new scan to produce fresh cards. Connector settings, PostgreSQL, calendars and identity-provider data are retained.
Start Clew again after reset. If bootstrap detects executions carrying the old in-process fixture contracts, it requires
this explicit cutover before registration; deleting the old source cannot reconstruct its results.

Checks:

```sh
docker exec -w /workspace clew-app-1 bun run check      # tsc + dependency rules (D20) + Bun unit tests + Node runtime tests; also runs in CI
docker exec -w /workspace clew-app-1 bun run test:node  # current server runtime, without external services
docker exec -w /workspace clew-app-1 bun run test:db    # PostgreSQL contracts
docker exec -w /workspace clew-app-1 bun run test:durability # PostgreSQL/DBOS/Node synthetic reliability scenarios
sh scripts/a11y.sh menu.spec.ts --timeout 15000         # on the host: the WCAG specs a change touches, failing fast (D51); the full suite runs by hand until the run-up to a release (D59)
sh scripts/a11y.sh                                      # the whole WCAG 2.2 AA suite, as the workflow runs it: about eight minutes, not a per-edit check
```

Ports on loopback: 3020 web, 3021 Nextcloud (`calendar-admin`), 3022 Mailpit, 3024 the portal, 4040 to 4046 the fixture connectors, 4047 the local fake of Microsoft Graph (`/v1.0`).

The durable engine (DBOS Transact, D85) runs inside the BFF and checkpoints to the `dbos` schema of the development database; there is no separate service or UI. Approved executions, reminder/snooze timers, bounded calendar follow-up and scheduled jobs use durable PostgreSQL intent before dispatch. A reminder keeps its absolute due time through an outage; queued/blocked states remain visible. Inspect workflows with SQL (`select workflow_uuid, name, status, executor_id, application_version from dbos.workflow_status order by created_at desc limit 50` through `docker exec clew-postgres-1 psql -U clew clew`) and aggregates with `docker exec -w /workspace clew-app-1 bun scripts/reliability-status.ts`. See [scheduled work](../architecture/scheduled-work.md) and the [operations runbook](reliability-operations.md).

The older login/connector smoke scripts assume synchronous source decisions; they are not acceptance evidence for the new asynchronous paths. See [testing](../architecture/testing.md) for the maintained suites and remaining live-source checks.

The calendar image refreshes its pinned Calendar and RoomVox code in an existing data volume before Apache starts, then runs Nextcloud's app migrations. Unchanged versions do nothing; a failed upgrade stays pending and is retried on restart. App downgrades are refused. Back up the calendar volume before applying upgrades; restoring older image pins alone does not undo database migrations.
