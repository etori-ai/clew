# Local development

For contributors running the full Clew application. Connector authors can start with the [connector quickstart](../guides/creating-a-connector.md), whose first check needs no running services.

Host commands below start Docker infrastructure; application commands run inside `clew-app-1` at `/workspace`. These instructions use the shared local Keycloak container and are not a production deployment recipe.

## Run it

Everything runs in Docker. Commands go through `docker exec` into the app container (Claude Code and most editors sit outside the devcontainer).

```sh
sh scripts/compose.sh up -d --build --wait              # the app image (Node 26.13.0 LTS + Bun 1.4.4), Postgres 17, Temporal and the six fixture connectors
docker exec -w /workspace clew-app-1 bun install --frozen-lockfile
docker exec -w /workspace clew-app-1 bun run db:init     # Drizzle migrations
docker exec -w /workspace clew-app-1 bun run dev:connectors  # registers the fixture connectors and binds the job followers (D61); run again after a manifest change
docker start keycloak                                    # the shared local Keycloak 26.2 at keycloak.orb.local:8090
docker inspect keycloak --format '{{json .Config.Env}}' | docker exec -i -w /workspace clew-app-1 bun run auth:setup
sh scripts/calendar.sh start                             # Nextcloud CalDAV provider + Mailpit, seeded with synthetic people and meetings
docker exec -it -w /workspace clew-app-1 bun run dev                 # BFF on :3000 and Vite on :5173, published as http://localhost:3020
```

Open http://localhost:3020. Synthetic accounts: `hillevi` (rektor, manager persona), `hassan` (undersköterska, employee persona) and `mikael` (systemförvaltare, `admin.connectors`). Each has a Nextcloud calendar; `calendar.sh seed` gives all three a week of meetings. Passwords are generated by `auth:setup` into the ignored `.auth-test.env`; the BFF reads `apps/server/.env.local`, also ignored.

The cards on Hem come from the six fixture connectors in the stack, generic systems as independent services behind the connector protocol (D61): `hr` (Personalsystemet), `finance` (Ekonomisystemet), `incidents` (Avvikelsesystemet), `communication` (Kommunikation), `timesheet` (Tidrapporteringen) and `payroll` (Lönesystemet), under `connectors/`. Clew bundles only its core; the fixtures are registered like a vendor's connectors and show as such under Administration › Anslutna system. Their records are seeded relative to the day the stack first started and kept in SQLite on a volume each; `bun run fixtures:reset` (host or container) seeds them again from today and closes the cards they had pushed. A code change in a connector is `sh scripts/compose.sh restart <service>`. To see what Clew does when a source misbehaves, set `FIXTURE_FAULT` on one service (`unavailable`, `slow`, `unauthorized`, `conflict` or `crash-after-commit`) in an override or with `docker compose run`, and read the connector's README for the switches it supports.

Checks:

```sh
docker exec -w /workspace clew-app-1 bun run check      # tsc + dependency rules (D20) + Bun unit tests + Node runtime tests; also runs in CI
docker exec -w /workspace clew-app-1 bun run test:node  # current server runtime, without external services
docker exec -w /workspace clew-app-1 bun run test:db    # PostgreSQL contracts
docker exec -w /workspace clew-app-1 bun run test:durability # PostgreSQL/Temporal/Node synthetic reliability scenarios
sh scripts/a11y.sh menu.spec.ts --timeout 15000         # on the host: the WCAG specs a change touches, failing fast (D51); the full suite runs by hand until the run-up to a release (D59)
sh scripts/a11y.sh                                      # the whole WCAG 2.2 AA suite, as the workflow runs it: about eight minutes, not a per-edit check
```

Ports on loopback: 3020 web, 3021 Nextcloud (`calendar-admin`), 3022 Mailpit, 3023 Temporal UI.

Temporal (server and UI) starts with the base compose stack and creates its two databases in the shared Postgres on first start. The BFF runs the worker in-process. Approved executions, reminder/snooze timers, bounded calendar follow-up and scheduled jobs use durable PostgreSQL intent before Temporal dispatch. A reminder keeps its absolute due time through an outage; queued/blocked states remain visible. Follow workflows in the UI at http://localhost:3023 and inspect aggregates with `docker exec -w /workspace clew-app-1 bun scripts/reliability-status.ts`. See [scheduled work](../architecture/scheduled-work.md) and the [operations runbook](reliability-operations.md).

The older login/connector smoke scripts assume synchronous source decisions; they are not acceptance evidence for the new asynchronous paths. See [testing](../architecture/testing.md) for the maintained suites and remaining live-source checks.

The calendar image refreshes its pinned Calendar and RoomVox code in an existing data volume before Apache starts, then runs Nextcloud's app migrations. Unchanged versions do nothing; a failed upgrade stays pending and is retried on restart. App downgrades are refused. Back up the calendar volume before applying upgrades; restoring older image pins alone does not undo database migrations.
