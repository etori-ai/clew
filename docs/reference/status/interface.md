# Implementation status: pages and appearance

One page of [implementation status](../status.md). Each entry says what works in this checkout, what limits it or is still to do, and where the code and tests that show it are.

## Theme and logo

**Works in this checkout.** An installation's colours and header logo are saved in Clew's database on Administration › Utseende (`admin.appearance`, D98) and read by every browser from the public `GET /api/appearance`, the sign-in page included; no build variable and no restart. A theme is a Design Tokens (`.tokens.json`) file of Astryx's semantic colour tokens for the light and dark appearance, or two colours the page makes one from; a file is refused, with every problem named, when it sets an unknown colour or fails the WCAG contrast pairs. The logo is a stored PNG or SVG with an accessible name; an SVG with active content is refused. Each change is audited. The embedded `<site-header>` reads the same appearance through `appearance-src`.

**Limits and pending work.** Colour only: no typography, radius or component overrides from a file. No picture of the stored logo on the page (Astryx has no image component); no colour picker. Not exercised signed in against the development identity provider, and no manual screen-reader pass. Several instances would each need to re-read the row; a browser re-reads it on every visit.

**Evidence.** [D98](../../decisions/D98-the-installations-theme-and-logo-are-saved-in-clew-by-an-administrator.md), [branding guide](../../maintainers/branding.md), [theme file](../../../packages/contracts/src/theme-file.ts), [use cases](../../../apps/server/src/modules/appearance/usecases.ts), [tests](../../../tests/unit/appearance-admin.test.ts) The same changes are made from the command line with `bun scripts/appearance-set.ts <folder> | --reset | --show`, and `themes/clew/` (Clew's own look, [D126](../../decisions/D126-one-page-per-thing-one-astryx-template-per-page-type.md) item 11) and `themes/sundsvall/` are example folders with a theme file and a logo. An installation nobody has configured is still Astryx Neutral.

## Shared header

**Works in this checkout.** `packages/site-header` (D87, D88): one Astryx header for the web app and the intranet, the web app's top bar on every page ([D130](../../decisions/D130-clews-look-and-layout-are-the-startsidan-prototypes-built-with-astryx.md): there is no rail): a band with the logo and the site's name, the search, the reminder bell and the person, the places under them, and under the band the current place's own pages, which in the web app are Clew's own ([Clew's pages under the band](#clews-pages-under-the-band)); the intranet loads `<site-header>` (`bun run build:site-header`), rendered in a shadow root with the same theme and band. The places, their pages, the site's name and the logo come from the one connector an administrator chose with "Ger sidhuvudet" on its page among those whose manifest declares `header: { capability }` (`Governance.header`, exclusive, audited; `Registry.header`, `GET /api/header` for the signed-in person), else Clew's default with Start alone. Start is Clew's whatever the connector lists ([D116](../../decisions/D116-start-and-the-row-under-it-are-clews.md)): the server puts Start first, leading to `/` with no row of pages under it (amended 2026-11-13: Clew's places, Hem, Att göra, Kalender and, for a manager, Personal and Läget, stand once, since D130 in the row under the band), and leaves out a place the connector calls `start` or that leads to `/`. The holder is asked as the person with their provisioned groups, so an audience that names a group decides who gets its header; it answers under a three-second budget, and its answer is kept in the process per person, authorization version and set of groups, served again for a minute and then once more while a fresh one is read. A holder that refuses the person (the protocol's `denied`, with its 403) has answered that it lists nothing for them: the default takes the place of what was kept at that answer and is kept until the next refresh, so a content system takes a person's places away as fast as it narrows them, and the conformance check takes such a refusal for one of its people as the holder's answer. A holder that fails, its 401 for Clew's key or assertion included, does not answer in time or answers out of shape leaves the last good answer in place for up to an hour after it gave it (`HEADER_STALE_MS`), or the default when it has given none, and is asked again a minute later; after the hour the default stands until the holder answers. An answer is kept whatever was kept while it was asked, and a failure takes nothing's place, so of two reads at once the one that fails cannot undo the other's answer. Who may have the header is decided at every read, without asking the holder (`Registry.headerHolder`): when the holder is switched off as the holder or another is chosen, its audience narrowed to leave the person out, or the connector or its header capability switched off, what was kept is dropped at the next read, and so is it when the registry refuses the holder's answer because one of these changed while it was asked, judged on the governance read after the call whether the holder answered or not. A refusal by the registry is never kept, so a person let in gets the header at the next read (D88, amended 2026-11-13). `connectors/intranet` is the development fixture (port 4049), answering the menu, logo and site name from `connectors/intranet/menu.json` (or `INTRANET_MENU_FILE`, with an optional `roles` per place), and `denied` for a person it lists no place for. The intranet may instead list its pages from Sitevision or WordPress through the embed's source adapters. The web app's dev server serves an intranet stand-in at `/intranat/`.

**Limits and pending work.** Not yet looked at signed in on the development stack; no screen-reader pass. The band is Vattjom, not the proof of concept's `#003c69`. No overflow menu (rows wrap). No editing of links or logo in Clew by decision: a connector owns the content, an administrator only chooses which. No Sitevision or SharePoint connector yet. The kept header lives in one process, so each instance keeps its own, and a header changed at the source, the source's refusal of the person included, reaches a person after the minute has passed, one page load later. While the holder is down, a person it has given nothing yet gets the default a minute at a time, and everyone gets it once the hour has passed.

## Alla verktyg and a tool's page

**Works in this checkout.** [D126](../../decisions/D126-one-page-per-thing-one-astryx-template-per-page-type.md) rules 1, 8 and 10. Alla verktyg (`/tools`, the `library` template) lists every tool the person may open where the "Verktyg" menu's first four end: the title and how many there are, a search field that narrows the tiles in place (its words in the address as `filter`, the count said as it changes), then the tools as uniform tiles in sections by the system they belong to, Clew's own first, then the systems in the order they were registered (`toolGroups`). A tile leads to the tool's page with this page as the way back, so Back returns to the tile. At the foot the intranet's own page of tools, when the shared header names one (D88). The tools are what the menu reads: the views an administrator placed (D40) and Clew's own lists the person has (Mina ärenden, Mina beställningar), which stood on Hem before. A tool's page is a register when its view is a list or a table (the name with the system's badge and "Fråga Clew", the view's search and choice and the count, the rows, each row's name the link to its own read's page) and a thing's page when it is one record, text or document (the way back, the title, "Fråga Clew", the read in the column, a record's facts in the end panel); nothing opens beside the rows. [Views and menu tools](views.md#views-and-menu-tools) has the view rules.

**Limits and pending work.** The tiles are not placed or ordered by an administrator. Browser scenarios in `tests/a11y/tools.spec.ts`; no signed-in pass and no screen-reader pass.
