# Interface spaces and navigation

Clew gives each space a stable job. **Going to a destination changes the main page. Opening something from the current task keeps that task underneath or beside it.** A provider integration does not choose a different navigation model. A URL identifies content; having its own URL does not make that content a page.

This is the current placement reference, consolidated in [D83](../decisions/D83-interface-spaces-have-stable-navigation-roles.md). It brings together [D42](../decisions/D42-a-tool-opens-as-a-page.md), [D50](../decisions/D50-the-conversation-is-the-column-and-the-panel-holds-what-it-is-about.md), [D66](../decisions/D66-the-panel-keeps-everything-opened-beside-the-page-as-tabs.md), [D72](../decisions/D72-the-day-is-the-pages-and-the-panel-holds-only-what-was-opened.md), the amendments to [D73](../decisions/D73-the-review-is-a-page-in-the-shell-with-an-address.md). Earlier bodies retain their historical wording; use their amendments and this reference when placing new content.

## Where content belongs

| Space | Responsibility | Examples and behavior |
|---|---|---|
| Navigation rail | Choose a standing destination or earlier conversation. | Home, Calendar, approved tools, Personal for a manager ([D94](../decisions/D94-a-manager-has-a-personal-section-listing-the-people-on-their-units.md)), Administration and conversation history. A row here changes the main page and identifies the current destination. |
| Main page | The place the person is working, including its conversation. | Home's work list, Calendar, the phone book, an assistant transcript or administration. A conversation occupies the main column; it is not moved into the detail sidebar. |
| Page content | Information that belongs to the destination without being opened. | Home's cards, I dag and Sedan i går. The day may occupy a right-hand grid column, but it is page content, not a panel tab replaced by an opened record. |
| Context panel | Keep related information beside the current task. | One opened thing: a work item, source record or declared view, never a list of cards. Native content uses the shared panel and its open-content menu. From one window width on every page that holds it, 1336 px (`BESIDE_FROM`), it is non-modal beside the page and the page gives way to it, drawing its own narrow layout; below that, on a short screen and on a phone it is the drawer over the page, under the same header ([D110](../decisions/D110-where-something-opens-is-decided-by-what-it-is.md), amended 2026-11-11). Closing returns to the opener or reveals another retained entry. |
| Focused overlay | Browse a contextual collection or complete an interaction while retaining the originating task. | A multi-row review and one person's utvecklingssamtal. Each lies over whichever page it was opened from, with its own part of that page's address (`review` and `step`, `talk`), and closes to the page as it was under it ([D110](../decisions/D110-where-something-opens-is-decided-by-what-it-is.md) rule 5). Use the existing end Drawer on desktop and the corresponding sheet flow on mobile. Something opened from an overlay's collection is one level deeper; close returns to the collection, then to the page. One focused overlay at a time: an address that names both draws the review. |
| Confirmation and feedback | Decide about the active interaction or report its result. | Keep the established inline confirmation for simple card actions; use a small Dialog when a separate decision is needed. It sits above its owning interaction. Receipts, banners and status announcements stay with the affected content. A toast supplements durable state; it does not replace it. |

The context panel and focused overlay are related side surfaces with different behavior: one keeps reference material available alongside work; the other temporarily takes focus. Do not give the same entry point a different role depending on the provider. Mobile changes presentation, not the navigation level or the destination reached on close. The existing native panel still uses its own responsive Drawer composition for views; this consolidation does not claim a rewrite of every native view to sheets.

## Placement and return rules

1. A standing tool selected from the rail opens its page. A record selected inside that tool opens beside or over the tool, preserving its search and filters. No control promotes a contextual view to its tool's page ([D110](../decisions/D110-where-something-opens-is-decided-by-what-it-is.md) rule 7): the tool is reached from the rail, where an administrator placed it.
2. A contextual chooser opens in an overlay over the page that launched it. It does not introduce a new main-page destination just because the chooser is a list.
3. Opening one item from a collection preserves that collection as its parent. Close and Escape dismiss the top interaction only. A confirmation closes back into the interaction that owns it, that interaction into its collection, and the collection into the originating page. A card opened directly from Home returns directly to Home. A review opened from a card in the drawer over Kalender closes to that card, and the card to Kalender.
4. Keep the originating path, filters, open native context and unsent composer text. Put the selected content in the address so Back/Forward and reload can reproduce it: a review over Personal under a lens is `/staff?show=<lens>&card=<threadId>&review=<threadId>`, and closing it keeps the lens and the card. A cold legacy link without an origin uses Home underneath; do not guess a prior page (`/cards/<threadId>/review` leads to `/?card=<threadId>&review=<threadId>`).
5. Astryx owns stacking, focus containment and responsive surfaces. Render stacked drawers as siblings. Return focus to the actual opener; if completion removed it, use the owning collection's section. Never send focus behind an open modal.
6. Opening, closing or navigating does not approve a source write. Current session, AI availability and source authorization still apply at every read/decision. Pending confirmations are cancelled when their owning interaction closes.
7. Name the selected content and provide a visible close action. Preserve the parent collection's scroll position while drilling into an item. Hidden views must not continue source calls.
8. Opening is not asking ([D110](../decisions/D110-where-something-opens-is-decided-by-what-it-is.md) rule 6). Opening a card or a view beside a page leaves the question box as it was; a card, a row or a search hit goes into the box only with "Lägg till i samtalet", which adds it as a chip and moves the focus to the box. The control is drawn only where the page has a box (Hem, a conversation, a tool's page) and nowhere else, not on a card or view in the drawer over Kalender or Administration either; it never leads to another page. A question sent with something open beside Hem opens the conversation with it beside the transcript, and "Stäng samtalet" returns to Hem as it stood.

A new interaction should be reviewable by naming its **origin, space, parent, close target, focus target and address**. If it cannot fit one of these roles, amend the decision before introducing another space. Do not resolve placement ad hoc inside a provider component.

## A person and a unit

[D97](../decisions/D97-a-source-says-what-its-rows-are-about-and-clew-places-them.md) applies rules 1 and 4 to entities ([Entities](../architecture/entities.md)). Personal is the destination; a person and a unit are pages, shown one way ([D110](../decisions/D110-where-something-opens-is-decided-by-what-it-is.md) rule 3): a name leads to the person's page, and nothing draws a person beside a list. When "Just nu" counts several cards, it leads to the person's page at "Behöver dig" (D110, amended 2026-11-11: the panel holds one opened thing). A card about a person or a unit, and the card an action about them makes, opens beside the page it was opened or started on and never on Hem (D110 rules 2 to 4); a card's "Granska N" opens its review over that same page, and the person's talk lies over the page its "Öppna samtalet" is on (D110 rule 5). No rail entry leads to a person or a unit.

`section` takes a capability name or `needs-you` for "Behöver dig"; `from` holds only a path inside Clew, the list's own address with nothing of its panel. Choosing another section on the person's page keeps what is open beside it. The panel stands beside every page from 1336 px and the page gives way: Personal draws its rows where its table (Astryx's `resolveColumnWidths` over the columns of "Alla" or the lens) no longer fits beside the panel, a person's page its drill-in below 1432 px, a tool's page its list below 1720 px. A person or unit the reader may not ask about is the panel's or the page's own "Personen finns inte" or "Enheten finns inte", the same answer as an unknown key. A talk is written in its existing drawer ([D96](../decisions/D96-talks-is-the-first-owned-domain-the-round-and-action-points-behind-a-profile.md)) over the page its "Öppna samtalet" is on, the row's menu on Personal or the talks section on the person's page, with that page's address kept and `talk=<personId>` added (`/staff?show=<lens>&talk=<personId>`, `/people/<key>?section=<capability>&from=%2Fstaff&talk=<personId>`); closing it leaves the page as it was, and a cold `/staff?talk=<personId>` is Personal with the talk over it. The talks source says so itself: its way in is a query alone, `?talk={id}`, which Clew adds to the page it is drawn on, while a path such as the unit's "Visa i Personal" is a page of its own. A card's own read unfolds inside the card (`open-card`, `open-action`, D110 amended), and the review of a card's rows one at a time lies over the page the card is on, with the card under it (D73 amended, D110 rule 5). The implementation is [the panel of any page](../../apps/web/src/components/page-panel.tsx), with [the card it draws](../../apps/web/src/components/card-panel.tsx), [the person page](../../apps/web/src/pages/person.tsx), [the unit page](../../apps/web/src/pages/unit.tsx), [Personal](../../apps/web/src/pages/staff.tsx) with [its parts](../../apps/web/src/pages/staff-parts.tsx), [a card's read](../../apps/web/src/components/card-read.tsx), and the addresses of [a person and a unit](../../apps/web/src/person-address.ts) and [the panel](../../apps/web/src/panel-address.ts); the browser scenarios are [Personal](../../tests/a11y/staff.spec.ts), [the person](../../tests/a11y/person.spec.ts) and [the unit](../../tests/a11y/unit.spec.ts), on routed data. No manual screen-reader pass has been made.

## Implementation and verification

- Every page has the panel ([D110](../decisions/D110-where-something-opens-is-decided-by-what-it-is.md) rule 2), from one hook: [the panel of a page](../../apps/web/src/components/page-panel.tsx). The address names what it holds the same way on every page: `card` and a view (`open`), with a card's read unfolded in the card (`open-card`, `open-action`). Hem, a tool's page, Personal, a person's page and a unit's page draw it beside their column from 1336 px, under the same header as the drawer below that; on every other page in the shell (Kalender, whose end slot holds its Förslag panel, and Administration, whose pages have no narrow layout) the shell draws it as the drawer over the page, and closing leaves the page as it was. A row's own view is a link wherever a view is drawn, a card's read included. A card opened from something that belongs to no page, a reminder under the bell, a toast's "Visa" or a card found by the rail's search, opens over the page the person is on, with that page's address kept (`/calendar?card=<threadId>`) and a review or a talk over the page let go of. A receipt's toast leads to Hem's tab for the card on Hem and to the card over the page anywhere else. A card the person no longer has says so in the panel ("Kortet finns inte längre bland dina kort."), and the page stays. The browser scenarios are in [the shell's](../../tests/a11y/shell.spec.ts), [Personal's](../../tests/a11y/staff.spec.ts), [the person's](../../tests/a11y/person.spec.ts) and [the unit's](../../tests/a11y/unit.spec.ts) specs, with the toasts in [reliability](../../tests/a11y/reliability.spec.ts) and [undo](../../tests/a11y/undo.spec.ts) and the search in [structure](../../tests/a11y/structure.spec.ts).
- Whether the page has a box is the conversation's state (`hasBox` in [the conversation](../../apps/web/src/components/conversation-context.tsx)), set while [the box](../../apps/web/src/components/composer.tsx) is mounted; every "Lägg till i samtalet" reads it. The browser scenarios are in [Hem's panel](../../tests/a11y/todo.spec.ts) (opening leaves the box, adding puts the card in it, asking carries it beside the transcript), [Personal's](../../tests/a11y/staff.spec.ts), [the person's](../../tests/a11y/person.spec.ts), [the unit's](../../tests/a11y/unit.spec.ts) and [the shell's](../../tests/a11y/shell.spec.ts) specs (no control without a box) and [a tool's page](../../tests/a11y/tools.spec.ts) (the control with one).
- [Native panel and retained entries](../../apps/web/src/components/panel.tsx), [panel addresses](../../apps/web/src/panel-address.ts), [review overlay](../../apps/web/src/components/review-overlay.tsx) with [its address](../../apps/web/src/review-address.ts), [talk overlay](../../apps/web/src/components/talk-overlay.tsx) with [its address and the one filler of a source's way in](../../apps/web/src/talk-address.ts).
- The focused overlays lie over the page they were opened on (D110 rule 5). The review is mounted once for every page of the session, after the page in the tree ([routes](../../apps/web/src/main.tsx)), so a cold open stacks it over the card the same update opens: Astryx stacks sibling drawers and sheets opened together in tree order, last-opened on top, and Escape closes the top one only. The talk is mounted by the pages that draw its way in (Personal, a person's page, a unit's page), after their panel. Closing either replaces the address with the same one without its part, and the review hands its decisions back to the card through the entry's state, so the card puts the focus on its "Granska N" wherever it is drawn. While one is open it names the browser tab, and the page's own name comes back when it closes ([page title](../../apps/web/src/page-title.ts)).
- Native panel and review behavior is covered by the [panel scenarios](../../tests/a11y/todo.spec.ts) and [review scenarios](../../tests/a11y/review.spec.ts) (over Hem, beside Personal, in a conversation's answer, over the drawer on Kalender, the address from before), the talk by [the talk scenarios](../../tests/a11y/talk.spec.ts) (over Personal and a person's page), and a review from Klart by [the document scenarios](../../tests/a11y/documents.spec.ts).

This is a placement contract. The stacked-overlay rules were first exercised by the MCP prototype, which left the code on 2026-11-11 ([closing note](../reviews/2026-11-11-external-mcp-chat-services-exploration.md)); the multi-row review is the focused overlay in the product now. Browser checks do not substitute for a manual screen-reader pass. The user's screenshots and existing Astryx compositions supplied the visual reference; the private design canvas remains unavailable.
