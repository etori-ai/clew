# Interface spaces and navigation

Clew gives each space a stable job. **Going to a destination changes the main page. Opening something from the current task keeps that task underneath or beside it.** A provider integration does not choose a different navigation model. A URL identifies content; having its own URL does not make that content a page.

This is the current placement reference, consolidated in [D83](../decisions/D83-interface-spaces-have-stable-navigation-roles.md). It brings together [D42](../decisions/D42-a-tool-opens-as-a-page.md), [D50](../decisions/D50-the-conversation-is-the-column-and-the-panel-holds-what-it-is-about.md), [D66](../decisions/D66-the-panel-keeps-everything-opened-beside-the-page-as-tabs.md), [D72](../decisions/D72-the-day-is-the-pages-and-the-panel-holds-only-what-was-opened.md), the amendments to [D73](../decisions/D73-the-review-is-a-page-in-the-shell-with-an-address.md). Earlier bodies retain their historical wording; use their amendments and this reference when placing new content.

## Where content belongs

| Space | Responsibility | Examples and behavior |
|---|---|---|
| Navigation rail | Choose a standing destination or earlier conversation. | Home, Calendar, approved tools, Personal for a manager ([D94](../decisions/D94-a-manager-has-a-personal-section-listing-the-people-on-their-units.md)), Administration and conversation history. A row here changes the main page and identifies the current destination. |
| Main page | The place the person is working, including its conversation. | Home's work list, Calendar, the phone book, an assistant transcript or administration. A conversation occupies the main column; it is not moved into the detail sidebar. |
| Page content | Information that belongs to the destination without being opened. | Home's cards, I dag and Sedan i går. The day may occupy a right-hand grid column, but it is page content, not a panel tab replaced by an opened record. |
| Context panel | Keep related information beside the current task. | An opened work item, source record or declared view. Native content uses the shared panel and its open-content menu; where space allows it is non-modal beside the page, otherwise it uses the existing responsive overlay. Closing returns to the opener or reveals another retained entry. |
| Focused overlay | Browse a contextual collection or complete an interaction while retaining the originating task. | A multi-row review. Use the existing end Drawer on desktop and the corresponding sheet flow on mobile. Something opened from an overlay's collection is one level deeper; close returns to the collection, then to the page. |
| Confirmation and feedback | Decide about the active interaction or report its result. | Keep the established inline confirmation for simple card actions; use a small Dialog when a separate decision is needed. It sits above its owning interaction. Receipts, banners and status announcements stay with the affected content. A toast supplements durable state; it does not replace it. |

The context panel and focused overlay are related side surfaces with different behavior: one keeps reference material available alongside work; the other temporarily takes focus. Do not give the same entry point a different role depending on the provider. Mobile changes presentation, not the navigation level or the destination reached on close. The existing native panel still uses its own responsive Drawer composition for views; this consolidation does not claim a rewrite of every native view to sheets.

## Placement and return rules

1. A standing tool selected from the rail opens its page. A record selected inside that tool opens beside or over the tool, preserving its search and filters. Only an explicit **Öppna som sida** action promotes a contextual view to an available tool page.
2. A contextual chooser opens in an overlay over the page that launched it. It does not introduce a new main-page destination just because the chooser is a list.
3. Opening one item from a collection preserves that collection as its parent. Close and Escape dismiss the top interaction only. A confirmation closes back into the interaction that owns it, that interaction into its collection, and the collection into the originating page. A card opened directly from Home returns directly to Home.
4. Keep the originating path, filters, open native context and unsent composer text. Put the selected content in the address so Back/Forward and reload can reproduce it. A cold legacy link without an origin uses Home underneath; do not guess a prior page.
5. Astryx owns stacking, focus containment and responsive surfaces. Render stacked drawers as siblings. Return focus to the actual opener; if completion removed it, use the owning collection's section. Never send focus behind an open modal.
6. Opening, closing or navigating does not approve a source write. Current session, AI availability and source authorization still apply at every read/decision. Pending confirmations are cancelled when their owning interaction closes.
7. Name the selected content and provide a visible close action. Preserve the parent collection's scroll position while drilling into an item. Hidden views must not continue source calls.

A new interaction should be reviewable by naming its **origin, space, parent, close target, focus target and address**. If it cannot fit one of these roles, amend the decision before introducing another space. Do not resolve placement ad hoc inside a provider component.

## A person and a unit

[D97](../decisions/D97-a-source-says-what-its-rows-are-about-and-clew-places-them.md) applies rules 1 and 4 to entities ([Entities](../architecture/entities.md)). Personal is the destination; a name in its list leads to the person's page; a unit is always a page. A person is still drawn beside the list when "Just nu" counts several cards; whether a person has a place beside the list at all is open (the product owner, 2026-11-11: one way to show a person, and no action that chooses where). No rail entry leads to a person or a unit.

| User action | Origin | Space | Close target | Focus target | Address example |
|---|---|---|---|---|---|
| Choose a lens | "Visa: Alla" on Personal | Main page: the list becomes the lens's view | "Alla" in the same menu | Back on the Visa button, which names the lens | `/staff?show=talks.person` |
| Open a person beside the list | "Just nu" with more than one card; a name in the compact list while something is open beside it | Context panel beside the list, which is drawn compact; a drawer over it where the panel does not fit or the screen is short | ✕ or Esc: the list with its lens; on a phone "‹ Personal" | Open: the person's name; another person taking the place is said aloud; close: the row's name link | `/staff?show=talks.person&person=johan` |
| Open a card about a person | "Just nu" with one card ("1 att agera på", "1 förslag"); a card under the opened person's Behöver dig | Context panel beside the list: in the list's panel, over the person when it was opened from them; the drawer where the panel does not fit. The card is the one Hem draws, with its own buttons; nothing is decided by opening it | ✕ or Esc: the person it was opened from, else the list with its lens | Open: the panel's heading "Kort", the card's title said aloud when it takes the person's place; close: the link that opened it | `/staff?card=<threadId>`, `/staff?person=johan&card=<threadId>` |
| Go into one section on a phone | A row in the person's list of sections | The same drawer | "Tillbaka", named "Tillbaka till <namn>" | In: the way back; out: the row it came from | `/staff?person=johan&person-section=hr.person` |
| Open the person as a page | A name on a row of Personal; "Öppna som sida"; a section's way into the source's fuller view; a row that names the person on Hem, in search or in a view | Main page | The trail "Du är här": Personal for the reader's own people, else the page in `from` when Clew can name it (Hem, Kalender, a tool); no trail without `from` | The page title is said; on a narrow window, into a section: "Tillbaka till Om <namn>", out: the row it came from | `/people/johan?section=hr.person&from=%2Fstaff` |
| Open a unit | "Läget på <enhet>" on Hem; the unit under a person's name; a row that names the unit | Main page | The trail to the page in `from` | The page title is said | `/units/unit-skola?from=%2F` |
| Start an action from a person's menu | The row menu on Personal; the opened person's buttons, "Fler" or, on a phone, "Åtgärder" | Hem, with the card beside it ([D50](../decisions/D50-the-conversation-is-the-column-and-the-panel-holds-what-it-is-about.md)) | Back: the page the action started on, with its lens and opened person | The card's heading | `/?card=<threadId>` |

`section` takes a capability name or `needs-you` for "Behöver dig"; `from` holds only a path inside Clew. A person or unit the reader may not ask about is the panel's or the page's own "Personen finns inte" or "Enheten finns inte", the same answer as an unknown key. A talk is written in its existing drawer over Personal, `/staff?talk=<personId>` ([D96](../decisions/D96-talks-is-the-first-owned-domain-the-round-and-action-points-behind-a-profile.md)), reached from the talks section's "Öppna samtalet". A card's own read lies over the card the same way (`open-card`, `open-action`); the review of a card's rows one at a time stays the drawer over Hem (D73). The implementation is [the person beside a list](../../apps/web/src/components/person-panel.tsx), [the panel of any page](../../apps/web/src/components/page-panel.tsx), with [the card it draws](../../apps/web/src/components/card-panel.tsx), [the person page](../../apps/web/src/pages/person.tsx), [the unit page](../../apps/web/src/pages/unit.tsx), [Personal](../../apps/web/src/pages/staff.tsx) and [the addresses](../../apps/web/src/person-address.ts); the browser scenarios are [Personal](../../tests/a11y/staff.spec.ts), [the person](../../tests/a11y/person.spec.ts) and [the unit](../../tests/a11y/unit.spec.ts), on routed data. No manual screen-reader pass has been made.

## Implementation and verification

- Every page has the panel ([D107](../decisions/D107-where-something-opens-is-decided-by-what-it-is.md) rule 2), from one hook: [the panel of a page](../../apps/web/src/components/page-panel.tsx). The address names what it holds the same way on every page: `card`, a card's read (`open-card`, `open-action`) and a view (`open`). Hem, a tool's page and Personal draw it beside their column; on every other page in the shell (Kalender, Administration, a person's and a unit's page) the shell draws it as the drawer over the page, and closing leaves the page as it was. A row's own view is a link wherever a view is drawn, a card's read included. Nothing links to a card over those other pages yet: cards opened from them still lead to Hem until the next change of D107 lands. The browser scenarios are in [the shell's](../../tests/a11y/shell.spec.ts) and [Personal's](../../tests/a11y/staff.spec.ts) specs.
- [Native panel and retained entries](../../apps/web/src/components/panel.tsx), [panel addresses](../../apps/web/src/panel-address.ts), [review overlay](../../apps/web/src/components/review-overlay.tsx).
- Native panel and review behavior is covered by the [panel scenarios](../../tests/a11y/todo.spec.ts) and [review scenarios](../../tests/a11y/review.spec.ts).
