# D83 · Interface spaces have stable navigation roles

**Status:** accepted; the placement rules for pages, panels, overlays and confirmations stand. The MCP catalogue and App flow it also placed left the code with D81's prototype on 2026-11-11 ([closing note](../reviews/2026-11-11-external-mcp-chat-services-exploration.md)) · **Date:** 2026-11-09 · **Area:** ui, product

**Decision.** Use [Interface spaces and navigation](../reference/interface-spaces.md) as the current placement reference. Navigation destinations own the main page; opened contextual information stays beside it; focused service and review interactions use the existing sidebar overlay; confirmations and feedback belong to the interaction that caused them. Page-owned information such as I dag is not panel content. A content address does not imply a full page.

**MCP application.** **Alla tjänster** opens **Tjänster i samtalet** in an end Drawer, or a tall BottomSheet on phones, retaining the launching page, filters and composer draft. Selecting a service opens a child overlay above the catalogue; closing returns to its entry, then closing the catalogue returns to its launcher. A delivery opened directly from Home remains a direct overlay. Source-write confirmation is above the service and never an implied consequence of navigation. The protected overlay stack (`apps/web/src/labs/mcp/services-overlay.tsx`) owns these sibling Astryx surfaces; service addresses (`apps/web/src/service-address.ts`) use `open-services=1`, `open-service` and `open-delivery`. Old catalogue routes redirect to the overlay over Home.

**Why.** The product owner identified the service catalogue's full-page navigation as inconsistent with its contextual purpose. The underlying distinction already existed in D42/D50, D66, D72 and the D73/D81 amendments, but a new feature had interpreted a list as a destination. Consolidating placement, hierarchy, close, focus and address rules prevents each integration from inventing its own navigation. Existing native panel tabs remain appropriate for reference material; the provider flow uses the existing focused overlay composition.

**Replaces.** D81's prototype presentation of the service catalogue as a full page. This does not replace D42's standing tool pages, D50/D66's persistent native context, D72's page-owned day or D73's amended review overlay. Earlier decision bodies remain historical; the linked reference states their current combined rules. No new component system, CSS, provider contract or backend permission is added.

**Verification.** The targeted MCP browser suite (`tests/a11y/mcp.spec.ts`) covers catalogue/App drill-in, close and focus return, draft/filter retention, Back/Forward/reload, old addresses, AI-off, completion and desktop/mobile accessibility. The existing native panel and review suites remain the owners of those established flows. Hillevi's dev account is the live visual check. Production MCP readiness and manual screen-reader conformance are not claimed.
