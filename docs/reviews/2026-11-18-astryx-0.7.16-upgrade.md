# Review: Astryx 0.7.13 to 0.7.16, what is new and what it changed here · 2026-11-18

Date: 2026-11-18

Reviewed: `@astryxdesign/core`, `@astryxdesign/cli` and `@astryxdesign/theme-neutral` 0.7.16 (published 2026-11-14),
from the GitHub release notes of v0.7.14, v0.7.15 and v0.7.16, the 0.7.16 package's own source and locale files, and
running Clew on it.
Status: upgraded; see Outcome for what was verified and what was not

## Question

The product owner asked what is new in Astryx since the version Clew had, and then for the upgrade.

## What is new that matters to Clew

**Date, time and number fields say why they refuse what was typed** (0.7.15, 0.7.16; WCAG 2.2 1.4.1 and 3.3.1).
Before, DateInput, TimeInput, DateTimeInput and NumberInput marked a draft invalid and announced it on every
keystroke, showed it only as secondary-coloured text, and dropped it at blur with no message. Now nothing is marked
while a person types; at Enter or blur the text stays, the field shows its own message as an error status ("Ogiltigt
datum", "Ogiltig tid", "Ogiltigt tal", a date outside `min` and `max`, a date the calendar does not have), sets
`aria-invalid` and announces it once. A caller's `error` status with a message still wins. What a form posts is
unchanged. New: `onEntryErrorChange` on all four, with a locale-free `kind`, and `entryErrorBehavior` on the fields and
`defaultEntryErrorBehavior` on FormLayout. Clew uses DateInput in six files, DateTimeInput and TimeInput in the two
calendar dialogs and NumberInput on two competence administration pages; none needed a code change.

**Tables can window columns** (0.7.16): `useTableColumnsVirtualization`, both axes together, and
`useTableInfiniteScroll`. This does not reach the competence matrix (D120): a column with the caller's own
`renderCell` is never admitted to windowing (`isFixedHeightColumn` in `Table/tableColumnAdmission.ts` admits only
columns Astryx registers itself), and Table still has no header row that stays in view. D120's TanStack Table and
TanStack Virtual stay, and its "still open in Astryx" stands as written.

**Keyboard and assistive technology.**

- The arrow-key hint that Toolbar, TabList and SegmentedControl show on first keyboard focus stays until an arrow key,
  Escape or focus leaving the group, instead of vanishing after 3 seconds (0.7.14, WCAG 1.4.13). Clew draws Toolbar in
  fourteen files and TabList in seven.
- Under forced colours (Windows contrast themes) primary and secondary Buttons, Popover, DropdownMenu, ContextMenu and
  an inline Dialog get a border (0.7.16).
- TopNav items with only `onClick` are buttons that Tab and Enter reach (0.7.14).
- Toast announces a body whose text comes from a component (0.7.16).
- Ctrl+Tab and Cmd+Tab on the first or last control of a modal no longer wrap inside it (0.7.15).

**The conversation.** ChatComposerInput no longer collapses to 0 px after a restyle, such as a Dialog that holds a
SegmentedControl unmounting, which left a composer nobody could type in (0.7.16). Markdown's text transforms read the
source once, so a long streamed answer no longer renders slower with each paragraph (0.7.16).

**Touch.** Under a finger, DropdownMenu and MoreMenu open as they are pressed instead of after a 500 ms hold (0.7.14;
`presentation="popover"` keeps the old way). Anchored layers slide in from the side they land on. BottomSheet answers
slow swipes in Safari and a flick on its content (0.7.14, 0.7.16).

**Other changes.** Calendar's `hasWeekNumbers` shows the ISO week of each row's Thursday (0.7.15); rows that start on
Monday, as Clew's do, were right before. A two-month calendar whose `max` is in the opening month shows it in the
second pane. Tokenizer joins an InputGroup and picks several in a row with `hasEntriesOnFocus`. TextArea takes
`htmlMaxLength`. Lightbox draws a caption band and closes on a click beside the photo. Many components keep their
refs at commit, so a render that React discards in a transition no longer leaves its values behind.

**The CLI.** Most of the CLI's notes are its experimental theme editor and theme preview. Clew's theme is an uploaded
Design Tokens file mapped by Clew's own code (D98), so neither is used. `search`, `build` and `docs` keep caches and
start faster. No codemod exists after 0.7.8, and `astryx upgrade --from 0.7.13` reports nothing to change.

**Still missing.** None of the gaps Clew's decisions record is closed: a general image component (D37), a `max-height`
on ScrollableArea, marking days that hold events in Calendar (D32), a gray Badge and an outlined status Card, a colour
input and an import of a token file (D98), and in Table a header that stays in view and windowing over the caller's
cells (D120).

## Swedish strings

Astryx's `sv-SE.json` holds 365 messages in 0.7.16 against 677 in English, the same 365 as in 0.7.13 while English
gained 35 (28 of them for Lab's media player). `packages/ui/src/locale.ts` adds the keys Clew reaches that the
catalogue lacks; this change adds four:

- `@astryx.numberInput.invalidNumber` ("Ogiltigt tal"), which NumberInput shows from 0.7.16.
- `@astryx.dateInput.nonexistentDate` and `@astryx.dateInput.outOfRangeDate`, which DateInput and DateTimeInput
  already used in 0.7.13 and which were English in Clew until now.
- `@astryx.timestamp.copyFailed` (0.7.15), on the copy button of a Timestamp's hover card when the clipboard refuses.

Left out because Clew does not reach them: the date field's format hint and calendar description (only for a calendar
other than the Gregorian), Lightbox's "more" and "less" (Clew's one Lightbox has no caption), Table's "Load more", the
rich-text editor and Lab. Not checked in this change: the older gaps in components Clew does use, such as Tokenizer's
sheet, Table's selection and column resizing, FileInput's file sizes and TextArea's counter.

## Dependencies

Recorded in the [licence record](../reference/licences.md): the three packages stay MIT with the same publisher and
provenance. The CLI brings `css-tree` (MIT), `@csstools/css-syntax-patches-for-csstree` (MIT-0) and `mdn-data`, which
is CC0-1.0; it joins the CC0 question already waiting for the product owner
([open questions](../maintainers/open-questions.md)).

## Outcome

- Pins moved to 0.7.16 in the root, `packages/ui` and `packages/site-header`; `bun.lock` follows. No codemod applies.
- `bun run check` is green on 0.7.16.
- The WCAG suite was run once in full on 0.7.16, in a compose project of its own that installed from this branch's
  lockfile: 1,099 tests, 908 passed, 176 skipped, 15 failed. The 15 were then run on `main` at 0.7.13 the same way.
  14 fail there with the same errors and are not from the upgrade: `action-dialog.spec.ts` 61, 319, 441 and 725,
  `admin-boarding.spec.ts:184`, `boarding.spec.ts:436`, `card-actions.spec.ts:400`, `competence-search.spec.ts:91`,
  `reflow.spec.ts:158`, `reliability.spec.ts:99`, `touch.spec.ts:39`, `undo.spec.ts:57`, `users.spec.ts:820` and
  `views.spec.ts:255`. The fifteenth, `users.spec.ts:934`, passed on `main` and passed three times of three alone on
  0.7.16; it failed once in the long run.
- Two specs say that the fields' own messages are Swedish: `action-dialog.spec.ts` types 30 February into the date of
  Annan tid and reads "Ange ett datum som finns", and `admin-competence.spec.ts` types 2,5 into Giltigt i and reads
  "Ogiltigt tal", each with `aria-invalid`, and that the message goes when the entry is corrected. Both pass on 0.7.16.
- Not done: a pass on a phone for the menus that open on a finger's press and the BottomSheet changes, a look in a
  forced-colours mode, and a screen-reader pass over the fields' new messages.
